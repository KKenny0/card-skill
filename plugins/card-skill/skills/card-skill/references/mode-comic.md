# comic：片刻札记

用连续画面承担当下的冲突与变化。文字补充背景、必要含义与结论边界，不替画面解释每一步。默认且唯一风格为 `moment-notes`；省略 variant 等价。保留 Studio 自由构图、SVG、对白、旁白与多张叙事能力。

## 从内容到分镜

1. 明确来源支持的变化：谁在注意什么，做了什么，新增信息如何改变回应。事实、原文观点、概念演绎、虚构情境分别标明，不把设计情境写成作者经历或历史复原。
2. 先写动作链，再选择镜头：建立位置与人物 → 显示尚未解决的张力 → 动作或视线转向 → 留下变化及其边界。格数按需要决定；四格不是必选模板，也不强制出血、大格或漫画特效。
3. 镜头距离承担信息：近景看手、视线与力度；中景看动作归属；远景揭示此前未见的条件。镜头之外的信息不能凭空成为事实。
4. 保持人物左右位置、服装、手臂数量和道具归属连续。交接需画出或让相邻镜头明确可推断。转折前后都保留关键背景，避免把短暂安顿画成冲突已经消失。
5. 人物有身体、目光和动作，不能退化成图标加箭头。意象必须参与行动，不能仅装饰文字。

已验证的参考：卢梭从回望岸上到注意触水的手，岸仍在；不确定性从要求保证到改变行动问题；双人情境通过拉远镜头揭示积水，再改变双方回应。它们不是需要套用的题材或固定情节。

## 纸面与文字

固定1080×1440（3:4），干净纸面、完整宋体、左对齐标题、细线与克制色彩。tone/design 只改颜色，不能改分镜或字体。不要默认纸张噪点、破损字形、速度线或网点纹理。

正文/对白至少36 CSS px，短标注至少24px；在360px预览检查。按词组与语义断行，可用 `.reading-unit` 保持短词组；不要整句 nowrap、逐字挤压或通过缩字塞满。留白服务停顿，镜头内容仍需清楚。

标题提出阅读角度；结语保留必要边界。不要给每格增加解释性旁白来补救不成立的动作。没有空间时调整镜头数量、文本或在规划阶段拆页，不裁掉结论或画面。

## 正式合同与插画

读取 `schemas/comic.json` 和 `assets/comic_template.html`。始终提供 `composition_required: true`、完整 `content_html` 和非空 `custom_css`。使用模板 `.panels` 区域，不改变画幅。SVG/HTML 自由构图继续支持。

需要栅格插画时，使用可选 `comic_art: {path, alt}`，在 `content_html` 中恰好放置一次 `{{COMIC_ART}}`。它代表一张完整分镜画面；格数和镜头比例在画面里确定。可把该占位符放进有明确尺寸的容器，并在其他区域排对白/结语。不要把占位符写进属性、注释或脚本；不要把图片写成 logo、远程 URL 或 data URL。

插画必须是安全绝对本地路径的静态 PNG/JPEG/WebP，单图≤32MiB、边长≤8192、≤4000万像素；每个 Visual Job 的概念插画按不同哈希合计≤32MiB/4000万像素。renderer 接收私有快照并封装图片；receipt 的 `comic_art_snapshot` 保存身份，独立于 `media_snapshots` 来源证据。发布时重新检查图片身份、尺寸、预算并重新截图。

有合适的用户插画先用原图；否则由调用 Agent 检查实际生图工具并生成。生成能力、认证和提示词不进入 renderer。没有可用生图能力时，可以使用足以表达动作的 SVG；不能用图标假装人物叙事已完成。确实做不到应说明限制。

## 检验与交付

走 Visual Job v3 → schema → renderer → capture → check-output → 宿主查看PNG → review → reviewed publisher。不可另写独立HTML截图充当正式交付。

视觉审核时，在同一份已检查 HTML 中临时隐藏文字，保持画面与几何不动，再查看360px预览：谁做了什么？从哪格开始变化？原因是画面可见还是靠脑补？最后是否误导成无条件结论？这是审核操作，不修改交付合同，也不把无字版当作必须交付的第二张卡。记录看不懂或道具连续性问题，不把机器通过等同于读者理解。

同一图的有字/无字检查不得重新生图。修订必须走正常重新渲染与审核流程。对生成图额外检查手、视线方向、人物数量、道具交接和重复画面。
