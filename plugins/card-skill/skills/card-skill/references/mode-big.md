# Big：一句暂记

唯一默认风格：干净纸面、完整的香萃等粗宋、左对齐、一处阅读重音。固定1080×1440（3:4）；不使用背景水印、做旧噪声或内框。tone/design 只改颜色。`ghost_char` 为兼容旧数据接受，但不再显示，也不计入可见证据。

## 内容职责

一张图承担一个判断或追问。短句可以只有一两行，不用填满画面。必要条件、否定、例外必须留在主文；多分支或完整论证改为规划 poster/whiteboard，不自动删字或替用户换 mode。

短判断：对象与判断之间可停一拍，否定词与被否定对象保持在同一行。
反问：先交代前提，再读完整问题。重音可以是“就”“保证”等逻辑词；不能强调被否定的观点后把它误读成结论。
条件判断：条件、让步与结果按语义分组；组内紧、组间停。“或”与“且”不可互换，必要条件不可写成充分条件。

## 结构化合同

旧 `phrase` + `<br>` + `accent_words` 仍可用，统一渲染为个人风格。已有 `attribution`、`brand_name` 和本地 `logo` 保留；缺省不自动署名。`phrase` 不自动改写、不自动选断点。

推荐用纯文本 `phrase` 加 `reading_lines`。每行 `text` 必须按顺序完整复现主文（空白除外），不能用新行内容替换或删掉原意。

```json
{
  "mode": "big",
  "phrase": "开始之前，一定要保证不会后悔吗？",
  "reading_lines": [
    {"text": "开始之前，", "font_size": 108},
    {"text": "一定要保证", "font_size": 132, "pause_before": "short"},
    {"text": "不会后悔吗？", "font_size": 144}
  ],
  "accent_words": ["保证"],
  "attribution": "读不确定性的暂记 · 一个关于选择的提问"
}
```

`reading_lines`：1–6行、总主文最多60字符；每行仅允许 `text`、可选 `font_size`（100–200px）和 `pause_before`（none/short/long，对应0/40/88px附加间隔）。首行无前置停顿。省略字号时沿用 renderer 的保守估算；显式逐行字号不被偷偷缩小。`accent_words` 至多一个非空词组，必须只出现一次并完整处于同一行。阅读计划中不允许 HTML。

建议区间：短句132–176px；普通句108–144px；较长条件句100–108px。它们是起点，不是按字数机械套用的模板。通常只需要两级字号；不要逐行递增制造没有语义依据的层级。

来源说明36px；可用换行隔开出处与必要理解边界。不能把主文放不下的关键条件移进小字。原文引语仍遵循 Visual Job 的证据规则，只由 long/poster 承载；big 可用于经授权的观点提炼、转述与阅读提问，不能冒充作者原话。

## 容量与检查

big 主文的实际行数上限为六行，其他 mode 的标题仍为三行。六行只是上界，并不保证任意字号、旁注与停顿都放得下。禁止拆否定结构、数量词、专名，禁止行首标点和无意义孤字。

保留真实浏览器检查：主文实际字号至少96px（公开阅读计划最低100px）、画布/容器边界、字体加载、孤行与文本溢出。实际放不下时在内容规划中调整语义分组或说明容量冲突；不截断、不隐藏、不绕过检查器。

两行短句、三行追问、五行带条件判断和六行边界有浏览器回归样例。不能由这些样例推断任意多语言长段都可用。

## 工作流

按 SKILL.md 的 Visual Job v3 流程：证据与计划 → render-job 候选 → check-output → 查看真实 PNG（含360px缩图）→ hash-bound review → 本地交付。单纯 HTML 生成不算完成。
